# 제품 개선 결정 기록

이 문서는 사용자 검토를 거쳐 채택·보류·배제한 편의성 개선안을 기록한다.
새 기능을 제안하거나 구현 범위를 정할 때 이 문서를 먼저 확인한다.

## 2026-08-06 QR 대기 화면 관리자 빠른 작업

- 도움말을 연 `?` 버튼은 다시 누르면 도움말을 닫는다. 별도의 닫기 버튼도
  유지해 두 경로를 모두 제공한다.
- 수업 종료 뒤 다음 수업 준비는 QR 대기 화면의 기존 관리자 아이콘→PIN 인증
  안에서 처리한다. `다음 수업 반으로 바로 변경`은 12개 고정 반 중 현재 반을
  제외한 반을 고르고 한 번 확인한 뒤 전환한다.
- 빠른 반 전환은 이전 수업을 종료하고 새 session ID를 발급한다. 이전 수업의
  임시 보충 명단은 다음 반으로 승계하지 않는다. 대상 반에 활성 소속 학생이
  없으면 관리자 화면에서 소속을 먼저 정리하도록 실패폐쇄한다.
- `현재 반에 보충 인원 추가 (이번 수업만)`은 현재 반 소속이 아니고 아직 이
  수업에 추가되지 않은 활성 학생만 보여준다. 선택은 현재 session에만 저장하며
  학생의 영구 반 소속은 변경하지 않는다.
- 두 작업 모두 관리자 PIN을 통과해야 하며 학생용 QR·도움말 UI에는 노출하지
  않는다. 이는 배제된 `직전 수업 구성 다시 시작` 기능이 아니라, 관리자가
  다음 고정 반을 명시적으로 새 세션으로 시작하는 단축 경로다.

남긴다. 사용자 화면, 통계 화면, 내보내기와 자동 재채점 기능은 만들지
않는다.

- 6번 중단 학습지 이어하기:
  - 이어하기 기능과 답안 복원 기능은 만들지 않는다.

- 7번 처리 단계·경과시간 표시:
  - 사용자 화면에 단계나 경과시간을 표시하지 않는다.
  - 로그인·페이지 준비·로그아웃·복구 같은 처리 단계가 기준 시간을
    초과한 경우에만 단계명과 제한된 소요시간을 기록한다.
  - 실제 문제 풀이 시간은 기록하지 않는다.
- 10번 오래 걸리는 작업 취소·재시도:
  - 사용자용 취소·재시도 버튼은 만들지 않는다.
  - 기존 안전 자동 재시도의 단계, 횟수, 타임아웃과 최종 실패 코드만
    기록한다.
- 29번 정답 이상 탐지와 재채점 미리보기:
  - 정답 이상 판단, 재채점과 미리보기 기능은 만들지 않는다.
  - 결과 판독 실패 시 실패 유형, 예상 문항 수와 판독 완료 수 같은
    구조적 개수만 기록한다.
  - 정답, 학생 답안, 점수, 틀린 문제 번호와 문항 내용은 기록하지 않는다.

이 대체 방침에도 30번의 저장 위치·크기 제한·열람 경로·민감정보 금지
규칙을 동일하게 적용한다. 12·19·20·22·27·28번에는 로그 대체 방침을
두지 않는다.

  않는다.
- 통신이 끊기면 현재 WebView와 답안을 유지한 채 입력을 가리고, 검증된

- 무입력 경고는 5분에 표시한다. 경고 후 1분 안에 `계속 채점`을 누르지

- 수식 키패드는 오른손 배치를 기본으로 하고 왼손·하단 중앙 프리셋을
  관리자 화면에서 선택한다.
- 관리자 실행취소는 30초 동안 제공하되 QR 재발급, 로그인정보 변경,

## 2026-08-02 QR 카드 출력 경로 결정

- Android `PrintManager`를 통한 단건·반 일괄 직접 인쇄는 제거한다.

- 반 전체 QR 재발급도 Android 인쇄 화면을 열지 않고 지정 PC PDF 전송으로
  완료한다.

## 2026-08-03 QR 카드 PDF 크기 결정

- 65×90mm 카드 케이스와 55×80mm 삽입 종이 크기는 유지한다.
- QR은 기존 30×30mm에서 40×40mm로 확대한다. QR 하단과 학생 이름 기준선
  사이 10mm 간격은 유지하고, QR 상단을 삽입 종이 상단에서 18mm로 옮긴다.

- 단건 PDF, 신규·변경 카드 PDF와 반 일괄 PDF는 같은 렌더러를 사용하므로
  모두 이 크기를 적용한다.
- 여러 장 PDF는 A4에 55×80mm 카드를 최대 3×3으로 배치하고 카드 사이에
  가로·세로 5mm 절단 여백을 둔다. 좌우 17.5mm, 상하 23.5mm에서 시작하며
  마지막 페이지는 필요한 카드만 왼쪽 위부터 채운다.
- 절단선은 제공된 기준 PDF와 같은 68% 회색·0.25pt로 표시한다.

## 2026-08-03 답안 현황판 바깥 터치 결정

- 현황판 밖에서 시작한 한 번의 터치는 현황판 닫기에만 사용한다.
- 손가락을 누르는 동안 현황판을 유지하고 손을 뗄 때 닫는다.
- 같은 제스처의 `pointerdown`, `pointerup`과 호환 `click`은 아래 답안 요소로
  전달하지 않는다.
- 현황판이 닫힌 뒤 사용자가 새로 누른 독립 터치부터 객관식 답, `모름`과 다른
  답안 입력을 허용한다.

## 2026-08-02 학생·반 관리자 작업 직렬화

- 학생·반·QR 카드 상태를 바꾸는 관리자 작업은 한 번에 하나만 실행한다.
- 학생 등록·수정·비활성화, 반 생성·삭제·소속 변경, CSV 적용, 실행취소,
  보강 학생 추가, 단건·일괄 카드 PDF 생성·지정 PC 전송이 같은 작업 gate를
  사용한다.
- 일괄 작업은 지정 PC의 PDF 저장 응답과 최신 관리자 목록 새로고침까지
  완료된 뒤 gate를 해제한다. 그동안 학생·반 선택 및 모든 변경 버튼을
  비활성화하고, 이미 열린 확인창의 늦은 실행 요청도 거부한다.

## 2026-08-02 비활성 학생 자격정보 최소화

- 학생 비활성화는 복구 가능한 보관 기능이 아니다. 기존 QR을 폐기하고 활성
  조회에서 제외하는 transaction에서 live DB 행의 아이디·비밀번호 암호문과
  IV도 즉시 빈 값으로 폐기한다.
- 기존 비활성 행은 DB v4 migration에서 같은 기준으로 정리한다. SQLite
  `secure_delete`를 사용하되 WAL·flash 저장장치의 물리적 보안 삭제를
  보장한다고 주장하지 않는다.

## 2026-08-02 신규·변경 카드 PDF 상태 의미

- 이 기능은 `생성 파일 검토 및 역질문` 작업에서 Codex가 “이름 변경·신규
  등록 등의 경우 카드 출력 필요 상태로 관리”하는 방안을 제안하고 사용자가
  `전부 추천안대로`라고 승인해 채택됐다. `needsPrint`라는 필드명이나 문구를
  사용자가 직접 지정한 것은 아니다.
- Room의 기존 `needsPrint`·`lastDeliveredAtEpochMs` 열 이름은 설치된 DB와의
  호환을 위해서만 유지한다. 제품 의미는 각각 `새 카드 PDF 생성 필요`와
  `지정 PC에 마지막으로 PDF 저장이 확인된 시각`이다.
- 지정 PC가 PDF 저장 ACK를 반환하면 생성 필요 상태를 해제한다. 이는 PDF가
  실제로 인쇄됐거나 학생에게 실물 카드가 전달됐다는 뜻이 아니다.
- 신규 등록·이름 변경·QR 재발급은 새 카드 PDF가 필요하다. 로그인정보 변경과
  반 소속 변경은 카드 표기나 QR 자체를 바꾸지 않으므로 기존 상태를 유지한다.
- 학생 비활성화와 QR 재발급은 기존 QR을 무효화한다. 이전에 저장한 PDF·실물
  카드도 더 이상 유효하지 않으며, 비활성 학생은 활성 카드 상태 목록에서
  제외한다.

## 2026-08-02 Web 과제별 문항 상태 격리

- Web SPA의 문항별 `답변/모름/미입력` 보조 상태는 브라우저 문서 전체에서
  공유하지 않고 과제별 scope에 저장한다.
- scope는 정규화한 경로·query와 서버 DOM이 제공하는 과제·학습지 식별자를
  우선 결합한다. 명시 식별자가 없을 때만 페이지 제목·표제·문항 수를
  제한적인 fallback 표식으로 사용한다.
- 최근 8개 scope만 메모리에 유지한다. 서버 답안을 대신 저장하거나 로그아웃
  때 서버 임시답안을 삭제하는 기능은 아니며, Kiosk가 추가한 화면 보조 상태의
  과제 간 누출만 방지한다.

## 2026-08-02 PC 페어링 비밀 DPAPI 보호

- PC 수신기 설정 v2는 256비트 페어링 비밀을 현재 Windows 사용자 범위의
  DPAPI로 보호하고 `secret_protected`만 저장한다. 평문이나 평문 Base64
  `secret` 필드는 새로 기록하지 않는다.
- 기존 v1 설정은 최초 load에서 길이·형식을 검증한 직후 v2 임시 파일로 쓰고
  원자적으로 교체한다. DPAPI 보호·설정 교체에 실패하면 평문 설정으로 계속
  운용하지 않고 수신기 시작을 실패시킨다.
- Windows 사용자 또는 PC를 바꾸면 기존 암호문을 복호화할 수 없다. 이 경우
  설정을 새로 만들고 태블릿과 물리적으로 다시 페어링한다.

## 2026-08-02 Web 로그아웃과 임시답안 보존

- Kiosk의 수업 종료는 공식 로그아웃 control 실행, 인증 cookie 제거, 로그인
  폼·자격정보 정리와 로그인 화면 재검증으로 인증 세션을 끝낸다.
- WebView origin storage 전체 삭제는 수행하지 않는다. `localStorage`,
  `sessionStorage`, IndexedDB 등 웹사이트가 미완료 답안을 보존하는 데 사용할
  수 있는 저장소를 Kiosk가 임의로 지우지 않는다.
- 서버가 공식 로그아웃 자체에서 임시답안을 어떻게 처리하는지는 Kiosk가
  보장하거나 변경하지 않는다. Kiosk는 제출되지 않은 답안을 자동 제출하거나
  서버 삭제 API를 호출하지 않는다.

## 2026-08-02 Web 복구와 관리자 데이터 변경 직렬화

- 수업 시작·종료 전 Web 로그인 상태를 정리하는 동안 학생·반·QR·CSV·카드
  PDF 관련 관리자 작업과 반 선택을 모두 차단한다.
- 반대로 학생·반 관리자 작업 중에는 Web 복구·수업 시작·종료를 시작하지
  않는다. 확인창이 먼저 열려 있었더라도 실제 실행 시 gate를 다시 검사한다.
- Web 복구 요청이 들고 간 시작 action은 복구가 끝날 때까지 관리자 데이터가
  바뀌지 않으므로 같은 반·보강학생 snapshot에 적용된다. Activity 재생성으로
  action이 사라지면 수업을 추측해 시작하지 않고 안전하게 다시 시도하게 한다.
