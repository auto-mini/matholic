# 연속 개발 Goal 호출 프롬프트

아래 본문만 Goal 입력란에 그대로 사용한다.

```text
작업을 시작하거나 자동 재개할 때마다
C:\Users\user\OneDrive\문서\매쓰홀릭 채점 키오스크\docs\CONTINUOUS_DEVELOPMENT_GOAL.md
파일 전체와 사용자 제공 AGENTS.md를 다시 읽고, 문서의 “현재 최우선 무인
운영 기준 — 2026-08-01”을 가장 높은 작업 기준으로 준수하라.

현재 A 기기와 PC에서 매쓰홀릭 채점 키오스크를 사람이 실제 사용하는 것처럼
직접 화면을 캡처하고 클릭·입력·스크롤하면서 관리자 → QR 대기 → 시험계정
로그인 → 학습지·진단평가 → 1·5·10·25문항 문제풀이 → 전체답안 → 결과 →
연속 채점 → 안전 종료·복구 흐름을 전방위적으로 검토하라. 기능 성공뿐 아니라
정렬, 잘림, 겹침, 여백, 터치 영역, 반응 지연, 깜박임, 늦게 보이는 불필요한
요소, 키패드, 스크롤, 회전, 오류 문구와 복구 가능성을 사람의 사용 관점에서
판단하라.

발견한 결함은 조사 → 가능하면 수정 전 실패하는 회귀시험 → 최소 구현 → 관련
자동시험 → 릴리스 빌드 → 안전한 A 보존형 설치 → 같은 실제 화면 흐름 재검증
→ 검토 순서로 처리하고 다음 고가치 범위로 반복하라. 테스트 계정의 1·5·10·
25문항 과제는 필요하면 제출·완료 처리해도 된다. 테스트 자료가 부족하면 필요한
문항 수·유형·조건·수량을 정확히 미검증 목록에 기록하되, 그것 없이 가능한
다른 의미 있는 작업을 계속하라.

관리자 PIN은 저장소 밖 DPAPI 파일이 존재할 때
scripts\enter-tablet-admin-pin.ps1 -RequireStoredPin 전용 도구로만 사용하고,
PIN 원문이나 복호화 결과를 읽거나 출력·기록하지 마라. 만료형 원격 지원과
시험 QR hash 경로는 헌장의 조건에 따라 사용하고 매 점검 뒤 화면·QR 임시
파일을 정리하라. QR hash 시험은 광학 인식을 증명하지 않으므로 카메라·실물
카드·반사·조명 검증과 구분해 보고하라.

헌장의 최신 체크포인트에 Lock Task NONE이 아직 미해결로 남아 있다면 첫
기기 작업은 최신 화면과 상태를 확인해 원인을 구분하고, 재부팅·데이터 삭제
없이 전용 HOME과 안전한 잠금 상태를 복원한 뒤 체크포인트를 갱신하는 것이다.
이후 같은 signer의 더 높은 versionCode APK만 adb install -r로 설치하고 설치
전후 UID, firstInstallTime, signer, Device Owner, HOME, Lock Task, 앱 상태와
충돌 로그를 확인하라.

사용자 개입이 필요한 실물·Windows 인증·USB·전원·프린터 항목은 미검증과
추후 요청 목록에 남기고 우회 가능한 다른 의미 있는 작업을 계속하라. 단,
우회 시험을 실제 광학·실물 시험 통과로 보고하지 마라. 공장초기화, Device
Owner 변경, 앱 데이터·DB·Keystore·PIN 초기화, 앱 삭제, A/PC 재부팅·종료,
USB 디버깅·ADB 승인·Wi-Fi·잠금·보안 설정 변경, 실제 인쇄, QR 재발급·폐기,
복구 불능 실패주입, Android Emulator·Hyper-V 사용은 금지한다.

한 가지 목적 또는 밀접한 결함 묶음마다 독립적으로 되돌릴 수 있는 작은
커밋을 만들고 현재 codex/ 작업 브랜치에 푸시하라. 사용자 기존 미커밋 변경과
diagnostics/, output/, tmp/의 기존 항목은 stage·commit·수정·삭제하지 마라.
수행하지 않은 검증은 완료로 보고하지 말고, 변경·검증·A 설치·커밋·푸시·
미검증·사용자 개입 대기를 사람이 이해할 수 있게 계속 기록하라.

사용자가 명시적으로 중단할 때까지 이 Goal을 완료 처리하지 말고 위 사이클을
계속하라. 알려진 결함이 잠시 소진되어도 근거 없는 변경을 만들지 말고 코드,
실제 화면, 경계 상태, 복구, 성능과 운영 문서에서 다음 고가치 검토 대상을
선택하라.
```
