# 알려진 제한과 잔여위험

## 2026-08-11 현재 운영 제한

- 현재 A 설치본은 Kiosk RC79/Web RC137이다. 보존 설치 뒤 UID·firstInstallTime,
  Device Owner·전용 HOME·Lock Task를 유지했고, QR 성공 안내 유지·자동 소멸과
  강화된 채점 종료 경고를 실물 확인했다.
- 페어링된 지정 PC의 로컬 Windows 로그인·채점 결과 알림은 현재 제품 범위에
  포함된다. 제거한 것은 제3자·클라우드 외부 알림이며, 5분 무입력 뒤 자동
  로그아웃은 별도 Windows 알림 없이 QR 화면으로 복귀하는 현재 정책을 유지한다.
- PC 수신기 0.1.7은 운영 설치·독립 자체 점검·listener 재기동을 통과했다.
  설치·제거 스크립트는 정확한 실행 파일의 광범위 인바운드 규칙을 제거하도록
  보강했다. 관리자 권한으로 기존 자동 규칙 6개를 제거한 뒤 설치본에 연결된
  `Private`/TCP 48129 단일 인바운드 규칙만 남았음을 독립 확인했다.
- 아래 RC별 항목은 해당 버전에서 확인한 역사적 위험 기록이다. 이후 버전의
  실기 통과가 명시된 항목은 현재 미검증으로 다시 해석하지 않는다.

- Gate 1 최종 FAIL: 기억하기 상태, 로그인 직후/홈 이동, 문제풀이 복귀와 프로필 진입에 필요한 의미 기반 상태·Action이 실제 SM-P610/매쓰홀릭 7.5.1 접근성 트리에 노출되지 않았다.
- 접근성 의미노드 의존: 현재 결과를 우회하려면 좌표·이미지·비공개 방식이 필요하지만 승인 범위와 실패폐쇄 원칙에 맞지 않아 사용하지 않는다. 공급사가 접근성 role·label·action을 제공한 새 버전에서만 재검증한다.
- 서버 UI 변경: versionName이 같아도 화면이 바뀔 수 있다. version 검사만으로 안전하지 않아 런타임 fingerprint가 필요하다.
- 학생 식별: 프로필에서 이름·아이디·학원명 후보를 찾았지만 resource ID나 의미 role이 없고 다른 계정으로 값 변화만 교차검증하지 않았다. 생산 selector로 확정할 수 없다.
- 로그아웃 검증: 일반 앱은 서버 세션 폐기를 직접 증명할 수 없다. 로그인 화면과 빈 입력란에 의한 운영상 UI 검증이다.
- K1 잠금: 접근성 overlay와 화면 고정의 기존 한계는 유지된다. Gate 5 alpha는 공장초기화한 A에서 Device Owner·전용 HOME·Lock Task로 홈·최근 앱·알림창·설정을 차단했지만, 이 결과를 일반 앱인 `poc`나 비-Device Owner 설치에 적용할 수 없다.
- restricted settings: Android 13 이상에서 sideload 접근성 서비스를 켜려면 사용자가 앱 정보에서 제한된 설정을 허용해야 할 수 있다. 자동 우회하지 않는다.
- 보고서 fingerprint: salt가 세션마다 바뀌므로 다른 Probe 프로세스의 digest는 직접 비교할 수 없다. 같은 캡처 세션 내 중복 판별용이다.
- bounds: 기기/창 크기 진단을 위해 저장하지만 selector로 사용하지 않는다.
- A/B 결과: SM-P610 전체 Gate 1과 SM-P613 기억하기 단축 재검증에서 같은 필수 실패가 재현됐다. B는 해당 실패만으로 Gate 1 PASS가 불가능해 인증 후 화면 반복 수집을 생략했다.
- 외부 알림: 제3자·클라우드 알림은 제거했다. 페어링된 지정 PC의 로컬 Windows
  로그인·채점 결과 알림은 구현·현장 확인된 현재 기능이다.
- 공급사 허용: 자동화 사용 가능하다는 사용자 확인을 근거로 진행하지만 법률 의견이나 계약 해석은 아니다. 문의 답변 원본 보관을 권장한다.
- 대화 노출: 시험계정의 이전 비밀번호가 대화에 입력됐지만 후속 시험 전에 변경해 해당 값은 무효화했다. 저장소에는 포함하지 않았다.
- Web POC 식별자 잔류: 공식 웹은 저장 checkbox가 해제되어도 로그아웃 뒤 이전 아이디를 다시 채운다. `webpoc`은 모든 로그인 페이지 로드에서 두 입력값을 비우고 checkbox를 해제한 뒤 재검증하지만, 이 동작이 실패하면 다음 학생 입력을 허용하지 않는다.
- WebView 임시 저장: 인증 중 access/refresh token이 공식 학습 웹의 WebView 저장소에 존재할 수 있다. 정상 로그아웃 뒤 Cookie/WebStorage/form data를 삭제하며, 민감 상태에서 재시작하면 안전 로그아웃·정리를 우선한다.
- Gate 5 alpha: A 한 대에서 Device Owner 잠금, QR→Web→QR 왕복과 재부팅 복구를 통과했다. 다른 제조사·Android 버전, 실제 학생 파일럿과 장시간 무인 운전 결과는 없다.
- Gate 5 패키징: 별도 release signer의 RC02 APK를 공장초기화한 A에 Device Owner로 배포했고 Android 폰과 별도 SanDisk USB의 PKCS12 키 복구본을 원본 SHA-256과 대조했다. 복구 비밀번호와 Windows DPAPI 자격정보는 USB에 넣지 않았다. 서명키 회전과 원격 업데이트 채널은 완료하지 않았다.
- 화면 회전: RC29/RC31은 세로 방향을 금지하면서 두 가로 방향을 센서로 선택한다. manifest·계측·release APK 선언 검증과 A의 QR·Web 화면 180도 실물 회전을 통과했다. 다른 제조사·Android 버전의 실기는 없다.
- USB 디버깅: A의 개발자 옵션과 USB 디버깅을 끄고 ADB에서 기기가 사라진 것을 확인한 뒤, 케이블을 분리해 물리 재부팅·자동 실행·복구와 잠금 경계를 재검증했다. 향후 USB 업데이트를 위해 디버깅을 다시 켜면 작업 직후 반드시 다시 끈다.
- Device Owner 복구: 관리자 PIN 분실이나 Device Owner 제거는 공장초기화가 필요하며 앱 DB, Keystore 키, 자격정보와 기존 QR을 복구하지 않는다.
- 관리자 PIN 지연은 앱 private DB의 wall clock 기준이다. 잠금 중 설정 진입은 차단하지만, 관리자 잠금 해제나 승인된 ADB를 가진 주체의 시각 변경·앱 데이터 삭제까지 방어하지 않는다.
- QR 카드 전달: Android 직접 인쇄 경로는 제거했고, 페어링된 지정 PC에 암호화된 PDF를 저장한 뒤 PC에서 검토·인쇄한다. 앱은 PC의 파일 저장 ACK까지만 확인하며 실제 인쇄·실물 전달 완료를 주장하지 않는다. PC 파일, 프린터 메모리와 대기열은 앱 밖의 신뢰 경계다.
- A의 기존 직접 인쇄 정체 작업: 기능 제거 전에 Android 내장 IPP 대기열에 남은 작업은 앱이 다시 사용하거나 정리하지 않는다. 필요하면 태블릿 OS의 인쇄 서비스 설정에서 별도로 제거해야 하며, 새 앱 흐름에는 직접 인쇄 재시험 항목이 없다.
- 선택적 PDF 공유: 65×90mm 카드 케이스용 55×80mm 삽입 종이·40×40mm QR PDF 공유 기능의 외부 수신 대상과 보관·삭제는 앱이 통제하지 못한다. 운영 기본은 지정 PC 암호화 전송이며, 공유 기능을 사용할 때만 통제된 대상을 선택하고 잔류 파일을 정리한다.
- 학생 비활성화: 기존 QR hash를 새 무작위 hash로 교체하고 활성 조회에서 제외하며, live DB 행의 아이디·비밀번호 암호문·IV를 즉시 빈 값으로 폐기한다. DB는 `secure_delete`를 사용하지만 SQLite WAL·저장장치 사본까지 물리적 보안 삭제됐다고 보장하지는 않는다.
- 카메라: `0.5.0-rc02`는 전면을 기본으로 사용하고 화면 버튼으로 후면 전환 및 다시 전면 복귀가 가능하다. A에서 두 렌즈 바인딩과 전면 실제 QR 왕복은 통과했지만 다른 모델의 전면 카메라 화질·초점·조명 성능은 측정하지 않았다.
- RC04 카메라: 사용자 얼굴 노출을 줄이기 위해 Preview를 제거하고 분석 스트림만 바인딩한다. 이후 A에서 전면·후면 바인딩과 RC61 출력·절단 카드의 실제 카메라 인식을 통과했다. 다른 모델·조명·코팅 반사 조건의 성능은 일반화하지 않는다.
- RC12 Web UI: 문제 입력 확대와 오답 번호 전용 결과는 2026-07-25 공개 Web 자산의 의미 구조에 맞춘 실패폐쇄 보조다. A 설치 Web POC RC12는 새 학생 문서 로드 시작부터 네이티브 불투명 화면을 먼저 표시하고, SPA 결과 전환에는 DOM observer를 사용하며, 인코딩이 모호하거나 fragment가 있는 학생 경로와 기본 HTTPS origin이 아닌 현재 문서·링크를 네이티브·DOM 정책에서 모두 거부한다. 로그인 문서는 query를 허용한 정확한 `/`, 로그인 확인·로그아웃 제어는 query를 허용한 정확한 `/course` 문서로 제한한다. 사이트 경로·DOM이 바뀌면 로그인 확인이나 로그아웃이 실패폐쇄될 수 있으므로 A 실기가 필요하다.
- RC12 Web 호출·로그인 경계: secure session은 정확한 Kiosk package와 같은 signer의 호출만 받고, 32자 Base64URL 1회용 handle로 고정 credential authority를 내부 구성한다. 로그인 form action은 정확한 HTTPS 인증 host의 기본 port·`/token/signin`이며 userinfo·query·fragment가 없을 때만 자격정보를 넣는다. 비신뢰 호출·변형 endpoint·변형 DOM origin·비-root 로그인 문서·비-course 포털 거부 시험을 통과했다. 이후 A의 QR→Web→QR과 정상 로그아웃도 통과했지만, 공식 사이트 구조가 바뀔 때는 다시 실패폐쇄·실기 확인한다.
- RC12 Web renderer 복구: renderer가 종료되면 사용할 수 없는 WebView를 계층에서 제거·파기하고 참조를 해제한 뒤 `WEB_PROCESS_GONE`으로 실패폐쇄한다. Android 13 일회용 에뮬레이터에서 강제 renderer 충돌과 새 WebView 복구를 통과했지만 A에서는 메모리 회수나 renderer 충돌을 고의로 주입하지 않았다.
- RC10 카메라 비동기 경계: 관리자 PIN 화면을 여는 순간 QR 분석을 중지하고 분석 세대를 바꿔 이미 처리 중이던 이전 프레임의 결과도 폐기한다. 폐기한 승인 결과의 QR token hash는 즉시 덮어쓴다. JVM 회귀시험과 Android 13 전체 계측은 통과했지만 A에서 QR 해석과 관리자 화면 진입을 의도적으로 겹치는 실기는 사용자 복귀 전까지 미검증이다.
- RC11 Web 준비 비동기 경계: QR 검증 뒤 자격정보 handle 준비가 끝나기 전에 scanner 화면을 떠나면 handle을 폐기하고 현재 상태가 정확히 `PRELOGIN_CHECK`일 때만 `QR_READY`로 복원한다. 정책 JVM 시험과 저장소 상태 전이 계측은 통과했지만 A에서 실제 QR 직후 교사 관리 버튼을 빠르게 누르는 실기는 사용자 복귀 전까지 미검증이다.
- RC08 관리자 안전성: 반 명단 조회 세대, 학생·수업 단일 실행, QR 재발급 확인, 활성 반 이름 중복 차단, 수업 저장소 불변조건, 늦은 Web 결과 차단과 보강 학생 배치 원자성은 자동시험을 통과했다. 이후 A에서 PIN 메뉴, 11개 반 전환 대상, 반 왕복, 보충 후보·추가와 세션 종료 정리를 실물 확인했다. 고의적인 프로세스 강제종료와 모든 빠른 연속 탭 조합은 별도 fault-injection 범위다.
- 생산 파일럿: RC02 핵심 왕복·비정상 복구·재부팅, 120분 연속 운전과 실제 프린터·종이 QR 왕복은 시험계정으로 통과했다. 실제 학생을 사용한 장기 운영 결과는 없다.
- RC30/RC32 역사적 실물 회귀: RC29/RC31에서 회전, 상단·계정 메뉴,
  오류신고·해설 문구, 제출 간격, 수식 기본 전환과 확인창 주소 머리말 제거는
  통과했다. 반면 학습지→진단평가 지연, 남은 동영상·필기·풀이 업로드,
  전체답안 자동 이동 실패, QR 목표 사각형의 의미 불명확과 25문항
  `RESULT_INCOMPLETE`를 재현했다. RC30/RC32는 공개 사이트 구조에 맞춰
  보강하고 자동검증·A 보존형 설치까지 완료했지만 실제 사이트 재검증 전이다.
