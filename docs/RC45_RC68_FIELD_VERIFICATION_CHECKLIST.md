## 검증 원칙

- 각 체크 항목의 담당 표시는 다음 의미다.
  - **자동**: 사용자 조작 없이 Codex가 실행하고 판정한다.
  - **공동**: PIN 입력·실물 QR 제시·시험 화면 진입처럼 짧은 사용자 조작이
    선행되면 Codex가 나머지 실행과 증거 확인을 담당한다.
  - **사용자**: 화면 체감, 터치감, 소리·진동, 실물 크기처럼 사용자가 직접
    조작하거나 판단해야 한다.
- 자동시험의 계약 검증과 실제 Matholic 현장 검증은 서로 대체하지 않는다.
  자동시험에 통과해도 실물 조작이 필요한 항목은 `공동` 또는 `사용자`로
  유지한다.
- 학생·반·QR 변경 시험은 가능한 한 테스트 계정과 테스트반으로 한다.
- 항목마다 `PASS`, `FAIL`, `미검증` 중 하나를 표시한다.
- 실패 시 반복 조작하기 전에 화면의 상태 코드와 재현 순서를 적는다.
- `LOCKED`, `MAINTENANCE_REQUIRED`, `RESULT_INCOMPLETE`가 나오면 상태 코드가
  보이는 사진을 찍고 안전 종료 절차를 먼저 사용한다.
- QR 재발급은 기존 QR을 폐기하므로 카드 전송·인쇄 시험은 일반 로그인
  회귀시험 뒤에 진행한다.
- 공장초기화, 앱 데이터 삭제와 Device Owner 변경은 이 체크리스트에 없다.

기록 형식:

```text
항목:
결과: PASS / FAIL / 미검증
상태 코드:
재현 순서:
사진·영상:
비고:
```

## 사용자 실기 최소 동선

`사용자` 106개는 106번의 별도 작업을 뜻하지 않는다. 사용자는
[최소 현장 검증 시나리오](RC45_RC68_MINIMAL_FIELD_SCENARIO.md)의 S1~S4만
순서대로 수행한다. Codex가 각 시나리오 시작 때 필요한 PC·ADB 준비를
끝내고 한 단계씩 안내하며, 완료 뒤 아래 세부 항목에 결과와 근거를 대신
반영한다.

직접 인쇄를 운영에 사용하지 않으면 16절의 태블릿 프린터 항목은
`미검증/운영상 미사용`으로 기록한다.
