# RC45/RC68 최소 현장 검증 시나리오

대상: A / SM-P610 / `R54TB029FHZ`

목표: `RC45_RC68_FIELD_VERIFICATION_CHECKLIST.md`의 남은 현장 항목을
중복 조작 없이 네 시나리오로 검증한다.

## 진행 방식

- 사용자는 한 번에 한 시나리오만 수행한다.
- 시작할 때 `S1 시작`처럼 알린다. Codex는 PC 수신기, ADB, 네트워크와
  비공개 진단 확인을 담당하고 사용자에게 필요한 다음 조작만 한 단계씩
  안내한다.
- 정상 종료 시 사용자는 `S1 완료 / 이상 없음`만 답한다.
- 문제가 생기면 반복하지 말고
  `S1 중단 / 단계 번호 / 화면 문구 또는 상태 코드`로 답한다.
- `LOCKED`, `MAINTENANCE_REQUIRED`, `RESULT_INCOMPLETE`가 보이면 그 자리에서
  멈춘다. Codex 확인 전 QR을 다시 찍거나 앱을 종료하지 않는다.
- 기존 운영 학생·반은 수정하지 않는다. 아래의 테스트 학생·테스트반만
  사용한다.
- 직접 태블릿 인쇄는 현재 운영에 쓰지 않으므로 `운영상 미사용`으로
  기록한다. PC 수신 PDF와 PC 인쇄만 검증한다.

## 한 번만 준비할 것

실행 직전에 Codex와 함께 다음 조건만 확인한다.

- 테스트반 T1, T2
  - T1은 가능하면 A·B만 둔 전용 회귀반으로 사용한다.
- 실제 Matholic 로그인이 가능한 테스트 학생 A, B
- A는 T1과 T2 양쪽 소속, B는 T1 소속
- A용 25문항 혼합 학습지와 10문항 학습지
- A/B/A 연속 회귀에 사용할 정답을 아는 1문항 학습지 세 개
- 현재 유효한 A, B의 종이 QR
- PC 수신기와 프린터

없는 항목은 S1의 CSV·관리자 작업에서 테스트 데이터로 만들되, 실제
Matholic 계정 자체를 임의로 새로 만들지는 않는다.

## S1. 복구·관리자·데이터·설정 한 번에 확인

예상 사용자 시간: 15~25분

Web 로그인: 없음

파괴적 작업: 테스트 데이터에 한정한 변경과 실행취소

### 사용자 조작

1. A에서 `RECOVERY_REQUIRED`와 보안 적용 표시를 확인한다.
2. PIN을 입력하고 안내되는 안전 복구를 실행한다.
3. 기존 학생·반·소속·QR 이력·테스트 계정이 남아 있는지 한 화면 흐름에서
   확인하고, 테스트반 생성 버튼과 일반 반 빠른선택도 정상인지 확인한다.
4. 관리자 화면에서 뒤로가기를 한 번 눌렀다가 돌아와 입력값과 화면이
   유지되는지 확인한다.
5. `운영 준비 자가진단`을 한 번 실행한다. 모든 기기 항목이 정상인지와
   실제 Matholic 로그인까지 보장한다고 잘못 표시하지 않는지 함께 확인한다.
6. Codex가 준비한 존재하지 않는 반 포함 CSV를 PC에서 대기시키면
   A의 `CSV 가져오기`를 누르고, 미리보기 뒤 거부되는지 확인한다.
7. Codex가 준비한 정상 CSV를 대기시키면 다시 가져와 미리보기와 적용을
   확인한다. 이 한 번으로 다음을 함께 확인한다.
   - 신규 학생 1명 생성
   - 기존 테스트 학생 1명 갱신
   - A의 T1·T2 중복 소속
   - 신규·변경 카드의 `출력 필요`
   - 화면에 아이디·비밀번호 원문 미노출
8. 테스트 데이터만 이용해 다음 작업을 각각 한 번 실행하고 곧바로
   `실행취소`한다.
   - 반에 학생 추가
   - 반에서 학생 제거
   - 학생 이름 변경
   - 테스트반 삭제
9. 마지막 이름 변경 하나는 실행 후 31초 기다려 실행취소가 만료되는지만
   확인한 뒤 수동으로 원래 이름을 복원한다.
10. 테스트 학생의 비밀번호 변경과 비활성화 화면에서 실행취소가 제공되지
    않는지 확인한다. 변경을 확정했다면 즉시 정상값·활성 상태로 되돌린다.
11. 기본 피드백이 `진동 켜짐 / 소리 꺼짐`인지 확인한다.
12. 다음 S2를 위해 `진동 켜짐 / 소리 켜짐 / 오른손 키패드`로 저장한다.
13. T1 수업을 시작해 `QR_READY`로 돌아온다.

### Codex 확인

- 안전 복구 전후 Device Owner, HOME, Lock Task
- 자가진단 항목과 실제 ADB 기준값의 일치
- PC 수신기 상태 왕복
- CSV 전송·적용 결과와 민감정보 로그 부재
- S1 뒤 앱 crash 및 private 진단 로그

### 이 시나리오가 처리하는 체크리스트

- 1절 전체
- 2절 전체
- 3절 전체
- 5절 전체
- 6절 전체 중 QR 재발급 관련 항목을 제외한 항목
- 7절의 기본값과 다음 세션용 오른손 프리셋

## S2. 한 번의 로그인으로 QR·입력·통신·10분·25/10문항 제출

예상 사용자 시간: 30~45분

Web 로그인: 학생 A 한 번

의도적인 대기: 10분 한 번

### A. QR 입구 확인

1. T1의 `QR_READY`에서 전면 카메라 안내가 실제 카메라와 일치하는지
   확인한다.
2. A 카드로 다음 동작을 각각 한 번만 한다.
   - 렌즈 왼쪽과 오른쪽에 두기
   - 렌즈에서 완전히 치우기
   - 그늘을 만들어 어둡게 하기
   - 조명에 기울여 강한 반사를 만들기
   - 너무 멀리 두거나 일부를 가려 흐림·저대비 만들기
3. 안내가 잠깐 나타났다가 조건이 사라지면 지워지는지 확인한다.
4. 얼굴과 일반 문서를 각각 보여도 로그인하지 않는지 확인한다.
5. T1에 속하지 않은 학생 QR을 한 번 보여 로그인되지 않는지 확인한다.
6. A의 유효 QR을 촬영하고 이름과 `취소`가 보이면 2초 안에 취소한다.
7. `QR_READY` 복귀 뒤 A의 QR을 다시 촬영하고 이번에는 취소하지 않는다.

같은 현상을 만들려고 세 번 이상 반복하지 않는다. 세 번 안에 품질 안내가
나오지 않으면 해당 안내만 FAIL로 기록하고 다음 단계로 간다.

### B. 로그인·화면·회전·PC 상태

8. 로그인 중 학생 A 이름, 자동 학습지 진입과 메뉴 숨김 상태를 확인한다.
   최상단 메뉴·학생 계정 메뉴·숨김 대상 버튼이 먼저 번쩍 보이지 않아야 한다.
9. 학습지 → 진단평가 → 학습지로 한 번 왕복하고 체감 지연을 확인한다.
10. 시스템 뒤로가기를 한 번 눌러 잠기거나 이탈하지 않는지 확인한다.
11. QR 화면과 Web 화면에서 A를 각각 180도 한 번 돌려 양방향 회전을
    확인한다.
12. 문제 화면에서 전원 버튼으로 화면을 한 번 껐다 켜 상태가 유지되는지
    확인한다.
13. 오른손 키패드가 저장대로 적용됐는지 확인한다.
14. Codex가 PC 수신기를 잠시 중지하는 동안 A에서 문제 이동과 입력이
    계속 되는지 확인한다. Codex가 수신기를 다시 시작하면 PC 상태판이
    다음 갱신에서 복구되는지 확인한다.

PC 전원을 끄면 Codex 연결까지 종료되므로, 이 항목은 같은 네트워크
실패조건인 수신기 프로세스 중지로 시험한다. A 입장에서는 지정 PC
endpoint가 응답하지 않는 상태가 동일하다.

### C. 25문항에서 입력 기능 전부 확인

15. 25문항 학습지를 연다. 문제·답안 영역의 높이와 답안칸·모름·이전·
    다음·제출 버튼의 크기가 실제 터치에 충분하고 잘리지 않는지 확인한다.
16. 처음 만나는 객관식에서 답을 선택하고 다음 문제로 갔다 돌아와 값이
    유지되는지 확인한다.
17. 처음 만나는 주관식 두 문제에서 다음을 한 번씩만 수행한다.
    - 한 자리 숫자 입력
    - 세 자리 이상 입력
    - 일부 삭제·수정 뒤 다른 문제 왕복
18. 입력기가 처음부터 수식 모드이고 기본 모드로 바꿀 수 없는지 확인한다.
    루트·분수·파이를 입력하고 방향키 네 개로 커서를 이동한다.
19. 짧은 삭제, 길게 연속 삭제 후 손을 떼어 정지, 실행취소, 다시실행,
    전체 지움 2단계 경고를 차례로 한 번씩 확인한다.
20. 다른 문제로 왕복해 최종 입력값이 유지되는지 확인한다.
21. 키패드와 버튼이 문제·입력칸·뒤로가기·채점 끝내기를 가리거나
    잘리지 않는지 확인한다.
22. 파란 직접입력·필기입력·원래 수식 툴바가 먼저 번쩍 보이지 않는지
    확인한다.
23. 답안 현황 지도를 한 번 열고 답변·모름·현재 문제·전체 문항 수를
    확인한다.
24. 빈 문제를 남긴 상태에서 `다음 미입력`, 끝에서 처음으로 순환,
    `이전 미입력`, 문제번호 직접 이동을 한 번씩 확인한다.

### D. 통신 단절과 10분 무입력

25. 현재 객관식·주관식 답을 기억하고 `네트워크 시험 준비완료`라고 답한다.
26. Codex가 A의 Wi-Fi를 ADB로 끊으면 연결 복구 대기 화면, 입력 차단과
    답안 비노출을 확인한다.
27. Codex가 Wi-Fi를 복구하면 재로그인 없이 원래 문제와 답이 유지되는지
    확인하고 입력 하나와 문제 이동 하나를 수행한다.
28. 정상 문제 화면에서 손을 떼고 `10분 대기 시작`이라고 답한다.
29. 10분 동안 A 화면을 절대 건드리지 않는다.
30. 경고가 뜨면 `계속 채점`을 눌러 같은 문제·답안으로 돌아오고, 입력
    하나를 추가해 타이머가 다시 시작되는지 확인한다.

### E. 25문항과 10문항 제출

31. 입력 기능 시험에 쓴 답도 지워 25문항을 모두 미입력으로 만든 뒤 첫
    `답안 제출`을 누른다.
32. 키패드 닫힘, 최초 한 번 맨 아래 이동, 최종 제출 버튼 위치를 확인한다.
33. 위로 스크롤해 미입력 번호를 확인하고 위치가 다시 강제로 내려가지
    않는지 확인한다.
34. 풀이 업로드·동영상·해설·오류신고·문제지 버튼이 없는지 확인한다.
35. 최종 제출을 눌러 미입력 경고에 사이트 주소 머리말이 없는지 확인하고
    제출을 확정한다.
36. 결과에 1~25번이 모두 틀린 번호로 표시되고 풀이·정답·점수는 보이지
    않는지 확인한다.
37. `다른 학습지 계속 채점`을 눌러 같은 학생 A의 10문항 학습지로 간다.
38. 10문항은 전부 `모름`으로 표시한다. `다음 미입력`이 엉뚱한 문제로
    이동하지 않는지 확인한 뒤 제출하고 결과에 1~10번이 모두 표시되는지
    대조한다.
39. `확인하고 채점 끝내기`를 눌러 `QR_READY`로 돌아온다.

### Codex 확인

- PC의 `QR_READY → 로그인 준비 → 로그인 → 채점 → QR_READY` 상태 순서
- PC 본문 학생 이름과 Windows 알림의 학생 이름 미노출
- 수신기 중단 중 A 독립 동작과 재시작 뒤 상태 복구
- Wi-Fi 단절·복구 시각과 앱 상태
- `RESULT_INCOMPLETE`, crash와 private 진단 로그
- S2 종료 뒤 오른손 프리셋을 왼손 프리셋으로 변경하도록 안내

### 이 시나리오가 처리하는 체크리스트

## S3. 잘못된 로그인 한 번으로 잠금·재시도·복구 확인

예상 사용자 시간: 10~15분

Web 로그인: 실패 한 번, 복구 확인 성공 한 번

대상: 학생 A 테스트 계정만

### 사용자 조작

1. PIN으로 관리자 화면에 들어가 학생 A의 저장 비밀번호를 임시 오답으로
   바꾼다.
2. 실행취소 버튼이 제공되지 않는지 확인한다.
3. T1 수업을 시작하고 A QR을 한 번만 촬영한다.
4. 앱이 자체 제한 횟수만큼 처리할 때까지 QR을 다시 찍거나 화면을
   누르지 않는다.
5. 최종 실패 상태 코드에 아이디·비밀번호가 보이지 않고 무한 반복하지
   않는지 확인한다.
6. Windows 오류 알림에 학생 이름이 없는지 확인한다.
7. PIN을 입력해 `원버튼 복구`를 실행한다.
8. Web 세션과 현재 수업이 안전 종료되고 학생·반·QR은 남아 있는지
   확인한다.
9. 학생 A 비밀번호를 정상값으로 복원한다.
10. T1 수업을 다시 시작하고 같은 QR로 정상 로그인한다.
11. S2 뒤 저장한 왼손 키패드가 적용됐는지 확인한다.
12. 문제 화면까지 확인한 뒤 `채점 끝내기`로 `QR_READY`에 복귀한다.
13. 다음 S4를 위해 `소리 꺼짐 / 진동 꺼짐 / 하단 중앙 키패드`로 저장한다.

### Codex 확인

- 제한된 자동 재시도와 최종 상태
- 복구 중 사용자용 세부 재시도·경과시간 UI 부재
- 자격정보·학생정보가 없는 private 진단 로그

## S4. QR 재발급·PDF와 A→B→A 최종 회귀·재부팅

예상 사용자 시간: 20~35분

Web 로그인: 학생 A, 학생 B, 다른 반의 학생 A

비가역 변경: 테스트 학생 QR 재발급

### A. 재발급과 PC 전송

1. PIN으로 T1 관리 화면에 들어가 테스트 학생 A·B의 QR 재발급 미리보기를
   연다.
2. 영향 학생 수와 PDF 페이지 수를 확인하고 처음에는 취소한다.
3. 기존 QR이 그대로인지 확인한 뒤 다시 열어 재발급을 확정한다.
4. 실행취소가 제공되지 않는지 확인한다.
5. T1 수업을 시작해 기존 A·B 카드가 더 이상 로그인되지 않는지 각각
   한 번만 확인한 뒤 PIN으로 관리 화면에 돌아온다.
6. Codex가 PC 수신기를 중지하면 `현재 카드 지정 PC로 보내기`를 한 번
   눌러 실패가 전달 완료로 기록되지 않는지 확인한다.
7. Codex가 수신기를 다시 시작하면 같은 현재 카드를 재발급 없이 다시
   전송한다.
8. PC 저장 완료를 확인하고 같은 `미출력/변경 카드 PDF`를 다시 만들었을
   때 전달 완료된 변경 없는 카드가 제외되는지 확인한다.
9. Codex가 PDF의 페이지 수, 페이지당 최대 9장, 카드·QR·이름 위치와
   문서 크기를 자동 검사한다.
10. A·B 카드만 PC에서 인쇄한다. 태블릿 직접 인쇄는
    `미검증/운영상 미사용`으로 기록한다.
11. 카드 상태 화면의 발급·전달·출력 필요 상태와 시각을 확인한다.

### B. 새 카드 A → B → 다른 반 A

12. T1을 시작하고 새 A 카드로 로그인한다.
13. 소리·진동이 모두 꺼져 있고 하단 중앙 키패드가 적용됐는지 확인한다.
14. 정답을 아는 1문항 학습지에 일부러 오답을 제출한다.
15. `1번만 틀림`, 풀이·정답·점수 미표시와 `RESULT_INCOMPLETE` 부재를
    확인한 뒤 채점을 끝낸다.
16. 새 B 카드로 로그인해 다른 1문항 학습지에 정답을 제출한다.
17. `틀린 문제 없음`과 학생 이름이 A와 섞이지 않는지 확인한 뒤 끝낸다.
18. PIN으로 관리자 화면에 들어가 최종 선호 피드백과 키패드 프리셋을
    저장한 뒤 T2 수업으로 전환한다.
19. A의 같은 새 QR로 로그인해 A가 여러 반에서 같은 카드로 동작하고
    최종 선호 설정이 적용됐는지 확인한다.
20. 세 번째 1문항 학습지를 제출해 결과가 학생 B의 직전 결과와 섞이지
    않는지 확인하고 안전하게 채점을 끝낸다.

### C. 최종 재부팅

21. `QR_READY`에서 A를 재부팅한다.
22. Kiosk 자동 실행과 이탈 차단을 확인한다.
23. `RECOVERY_REQUIRED`면 PIN 안전 복구를 한 번 수행하고 T2 수업을
    다시 시작한다.
24. 최종 `QR_READY`와 오류 코드 없음 상태에서 멈춘다.
